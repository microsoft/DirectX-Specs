<!-- d3d12-review-alert:begin:indirect-execution:N-overview:0 -->

> [!WARNING]
> **Authored synthesis - human review pending.**
>
> A command signature describes a fixed-format record of arguments and state changes followed by one work command. `ExecuteIndirect` interprets an array of these records on the GPU. Recording the call does not capture the argument buffer or count buffer contents.

<!-- d3d12-review-alert:end:indirect-execution:N-overview:0 -->

<!-- d3d12-review-alert:begin:indirect-execution:N-overview:1 -->

> [!WARNING]
> **Authored synthesis - human review pending.**
>
> The command signature selects the record format, not a pipeline, shaders, render targets or descriptor heaps. State not supplied by the signature is inherited from the command list. The selected work command retains the direct operation's pipeline, resource, dimension and execution context requirements.

<!-- d3d12-review-alert:end:indirect-execution:N-overview:1 -->

For example, suppose an application wants a unique root constant to be
specified per-draw call in the indirect argument buffer. The application
would create a command signature that enables the indirect argument
buffer to specify the following parameters per draw call:

- Draw arguments (Vertex Count, Instance Count, ...)

- The value of 1 root constant

the root constant. The number of draw calls can be specified in a separate
GPU-visible buffer or by `MaxCommandCount`.<!-- d3d12-review-inline:end:indirect-execution:D-overview-example:2 --></ins>

## Command signatures and argument descriptions

<!-- d3d12-review-alert:begin:indirect-execution:N-object:0 -->

> [!WARNING]
> **Authored synthesis - human review pending.**
>
> `ID3D12CommandSignature` derives from `ID3D12Pageable`, which derives from `ID3D12DeviceChild` and `ID3D12Object`, then `IUnknown`. It declares no additional methods. The standard inherited object, device child and pageable responsibilities are unchanged; inherited methods are not separate command signature APIs.

<!-- d3d12-review-alert:end:indirect-execution:N-object:0 -->

<!-- d3d12-review-alert:begin:indirect-execution:N-object:1 -->

> [!WARNING]
> **Authored synthesis - human review pending.**
>
> The command signature retains its root signature object. The application must keep the command signature, argument/count resources, and resources addressed by argument GPU virtual addresses alive and resident for their GPU use, following [execution lifetime](execution.md#lifetime) and [residency](resources.md#residency). Command recording does not take ownership of application storage or freeze its contents.

<a id="command-signature-desc"></a>

### D3D12_COMMAND_SIGNATURE_DESC

```cpp
typedef struct D3D12_COMMAND_SIGNATURE_DESC
{
    // The number of bytes between each drawing structure
    UINT ByteStride;
    UINT NumArgumentDescs;
    const D3D12_INDIRECT_ARGUMENT_DESC* pArgumentDescs;
    UINT NodeMask;
} D3D12_COMMAND_SIGNATURE_DESC;
```

#### Members

`ByteStride`

Specifies the size of each command in the drawing buffer, in bytes.

`NumArgumentDescs`

Specifies the number of arguments in the command signature.

`pArgumentDescs`

An array of [D3D12_INDIRECT_ARGUMENT_DESC](#indirect-argument-desc) structures, containing details of the arguments, including whether the argument is a vertex buffer, constant, constant buffer view, shader resource view, or unordered access view.

`NodeMask`

For single GPU operation, set this to zero. If there are multiple GPU nodes, set bits to identify the nodes (the device's physical adapters) for which the command signature is to apply. Each bit in the mask corresponds to a single node. Refer to [Multi-adapter systems](devices-and-capabilities.md#identity).

### D3D12_INDIRECT_ARGUMENT_DESC

```cpp
typedef struct D3D12_INDIRECT_ARGUMENT_DESC
{
    D3D12_INDIRECT_ARGUMENT_TYPE Type;

    union
    {
        struct
        {
            UINT Slot;
        } VertexBuffer;

        struct
        {
            UINT RootParameterIndex;
            UINT DestOffsetIn32BitValues;
            UINT Num32BitValuesToSet;
        } Constant;

        struct
        {
            UINT RootParameterIndex;
        } ConstantBufferView;

        struct
        {
            UINT RootParameterIndex;
        } ShaderResourceView;

        struct
        {
            UINT RootParameterIndex;
        } UnorderedAccessView;

        // Tier 1.1 support
        struct
        {
            UINT RootParameterIndex;
            UINT DestOffsetIn32BitValues;
        } IncrementingConstant;
    };
} D3D12_INDIRECT_ARGUMENT_DESC;
```

#### Members

`Type`

A single [D3D12_INDIRECT_ARGUMENT_TYPE](#indirect-argument-type) enumeration constant.

`VertexBuffer.Slot`

Specifies the slot containing the vertex buffer address.

`Constant.RootParameterIndex`

Specifies the root index of the constant.

`Constant.DestOffsetIn32BitValues`

The offset, in 32-bit values, to set the first constant of the group. Supports multi-value constants at a given root index. Root constant entries must be sorted from smallest to largest DestOffsetIn32BitValues.

`Constant.Num32BitValuesToSet`

The number of 32-bit constants that are set at the given root index. Supports multi-value constants at a given root index.

`ConstantBufferView.RootParameterIndex`

Specifies the root index of the CBV.

`ShaderResourceView.RootParameterIndex`

Specifies the root index of the SRV.

`UnorderedAccessView.RootParameterIndex`

Specifies the root index of the UAV.

`IncrementingConstant.RootParameterIndex`

<ins><!-- d3d12-review-inline:begin:indirect-execution:P-argument-members:18 -->Specifies the root constant parameter index.<!-- d3d12-review-inline:end:indirect-execution:P-argument-members:18 --></ins>

`IncrementingConstant.DestOffsetIn32BitValues`

<ins><!-- d3d12-review-inline:begin:indirect-execution:P-argument-members:20 -->Specifies the single 32-bit constant to update within that parameter.<!-- d3d12-review-inline:end:indirect-execution:P-argument-members:20 --></ins>

## Argument records and packing

<ins><!-- d3d12-review-inline:begin:indirect-execution:D-packing:0 -->The ordering of arguments within an indirect argument buffer is defined
to exactly match the order of arguments specified in
`D3D12_COMMAND_SIGNATURE_DESC::pArgumentDescs`. All of the arguments for 1
draw/dispatch call within an indirect argument buffer are tightly
packed. However, applications are allowed to specify an arbitrary byte
stride between draw/dispatch commands in an indirect argument buffer.<!-- d3d12-review-inline:end:indirect-execution:D-packing:0 --></ins>

> |---|---|---:|
> | `DRAW` | `D3D12_DRAW_ARGUMENTS` | 16 |

> | `DISPATCH` | `D3D12_DISPATCH_ARGUMENTS` | 12 |
> | `VERTEX_BUFFER_VIEW` | `BufferLocation` (64 bits), `SizeInBytes`, `StrideInBytes` | 16 |

> | `DISPATCH_MESH` | `D3D12_DISPATCH_MESH_ARGUMENTS` | 12 |
> | `INCREMENTING_CONSTANT` | No argument buffer payload | 0 |

<!-- d3d12-review-alert:end:indirect-execution:N-layout-table:1 -->

<!-- d3d12-review-alert:begin:indirect-execution:N-layout-table:2 -->

> [!WARNING]
> **Authored synthesis - human review pending.**
>
> Argument offsets are the prefix sum of these payload sizes in descriptor order. There is no implicit alignment gap between arguments, including before an eight-byte GPU virtual address. `ByteStride` must be four-byte aligned and at least the sum of the payload sizes. Additional bytes may occur after the argument payload and before the next record.

<!-- d3d12-review-alert:end:indirect-execution:N-layout-table:2 -->

<!-- d3d12-review-alert:begin:indirect-execution:N-layout-table:3 -->

> [!WARNING]
> **Authored synthesis - human review pending.**
>
> Within `D3D12_DISPATCH_RAYS_DESC`, `RayGenerationShaderRecord` occupies bytes 0–15; `MissShaderTable`, `HitGroupTable` and `CallableShaderTable` occupy 16–39, 40–63 and 64–87. `Width`, `Height` and `Depth` occupy 88–91, 92–95 and 96–99; bytes 100–103 are trailing structure padding. The ranges store `StartAddress`, then `SizeInBytes`, and, where present, `StrideInBytes`, each as 64-bit values. Tightly packed argument concatenation does not remove padding *inside* the public payload structure. A host C++ aggregate can also introduce padding *between* its members; such padding must not be mistaken for the signature-defined layout. Serialize to the prescribed offsets or make the host layout match them.

<a id="dispatch-arguments"></a>

### Dispatch fields and deferred reads

<ins><!-- d3d12-review-inline:begin:indirect-execution:A-18.6.5:0 -->`DISPATCH` takes the information about how many thread groups to dispatch from a buffer on the GPU. When the command reaches the GPU for execution, at that time the parameters are read from the GPU buffer. The point is that the parameters may have been written by some other GPU operation, possibly after the actual issuing of the `ExecuteIndirect` call from the CPU.<!-- d3d12-review-inline:end:indirect-execution:A-18.6.5:0 --></ins>

<ins><!-- d3d12-review-inline:begin:indirect-execution:A-18.6.5:1 -->At the specified record offset, the three `UINT` data members `ThreadGroupCountX`, `ThreadGroupCountY` and `ThreadGroupCountZ` of [D3D12_DISPATCH_ARGUMENTS](#argument-records) will be read.<!-- d3d12-review-inline:end:indirect-execution:A-18.6.5:1 --></ins>

<ins><!-- d3d12-review-inline:begin:indirect-execution:A-18.6.5:2 -->If any of the dispatch arguments are 0, the dispatch does nothing. The [shared dispatch dimension contract](compute.md#shared-grid-limits) defines the ordinary 65,535 per-axis limit and the capability-dependent expanded one-dimensional case, including its Y=Z=1 condition. Values larger than the applicable dimension bound produce undefined behavior. The [compute dispatch API](compute.md#dispatch) defines the workload and its pipeline/root state prerequisites.<!-- d3d12-review-inline:end:indirect-execution:A-18.6.5:2 --></ins>

<ins><!-- d3d12-review-inline:begin:indirect-execution:A-18.6.5:3 -->If the address range in the buffer where dispatch parameters will be fetched from goes out of bounds of the buffer, or the starting offset is not 4-byte aligned, behavior is undefined. D3D12 additionally performs the [recording time validation](#execute-validation).<!-- d3d12-review-inline:end:indirect-execution:A-18.6.5:3 --></ins>

## Work types, capabilities and selected state

<!-- d3d12-review-alert:begin:indirect-execution:N-work-types:0 -->

> [!WARNING]
> **Authored synthesis - human review pending.**
>
> Exactly one work argument is required, and it must be the last argument description. It is one of `DRAW`, `DRAW_INDEXED`, `DISPATCH`, `DISPATCH_RAYS` or `DISPATCH_MESH`. The remaining argument descriptions update state for that work. They do not add more work commands to a record.

<!-- d3d12-review-alert:end:indirect-execution:N-work-types:0 -->

<!-- d3d12-review-alert:begin:indirect-execution:N-work-types:1 -->

> [!WARNING]
> **Authored synthesis - human review pending.**
>
> | Final work argument | Root argument bind point | Workload and capability owner |
> |---|---|---|
> | `DRAW` / `DRAW_INDEXED` | Graphics | [Direct draws and IA/VS state](vertex-processing.md#direct-draws); [graphics pipelines](pipeline-state.md#graphics-description) |
> | `DISPATCH` | Compute | [Compute stage](compute.md#stage-model), [Dispatch](compute.md#dispatch), [grid dimensions](compute.md#shared-grid-limits) |
> | `DISPATCH_MESH` | Graphics | [MeshShaderTier and shader requirements](amplification-and-mesh-shaders.md#availability), [DispatchMesh](amplification-and-mesh-shaders.md#dispatchmesh), [AS payload/child grid contract](amplification-and-mesh-shaders.md#payload-and-amplification), [shared grid limits](compute.md#shared-grid-limits) |
> | `DISPATCH_RAYS` | Compute | [Raytracing tier 1.1](../Raytracing.md#d3d12_raytracing_tier), [DispatchRays](raytracing-pipelines.md#id3d12graphicscommandlist4dispatchrays), [descriptor and shader table limits](raytracing-pipelines.md#d3d12_dispatch_rays_desc) |

<!-- d3d12-review-alert:end:indirect-execution:N-work-types:1 -->

<!-- d3d12-review-alert:begin:indirect-execution:N-work-types:2 -->

> [!WARNING]
> **Authored synthesis - human review pending.**
>
> `DISPATCH_MESH` consumes the standalone three-`UINT` payload, not a new argument description union member. `ByteStride` includes the other selected arguments and any record-end padding. It is not required to equal 12 merely because the final work argument is a mesh dispatch.

<!-- d3d12-review-alert:end:indirect-execution:N-work-types:2 -->

<!-- d3d12-review-alert:begin:indirect-execution:N-work-types:3 -->

> [!WARNING]
> **Authored synthesis - human review pending.**
>
> The [full mesh/compute grid rules](compute.md#shared-grid-limits) apply to each record separately. Mesh grids retain their total group bound `X*Y*Z < 2^22`; expanded X does not increase Y or Z. An AS-launched child grid is distinct from the indirect parent grid. Each ray record retains shader table alignment/stride/extent and `Width*Height*Depth` limits from its exact descriptor owner. `MaxCommandCount` counts records, not vertices, instances, compute groups, AS-child groups or rays.

## ID3D12GraphicsCommandList::ExecuteIndirect

### Declaration

```cpp

    ID3D12CommandSignature* pCommandSignature,
```

### Behavior

There are 2 ways that command counts can be specified:

If pCountBuffer is not NULL, then MaxCommandCount specifies the maximum
number of operations which will be performed. The actual number of
operations to be performed are defined by the minimum of this value, and
a 32-bit unsigned integer contained in pCountBuffer (at the byte offset
specified by CountBufferOffset).

<ins><!-- d3d12-review-inline:begin:indirect-execution:D-count:2 -->If pCountBuffer is NULL, the MaxCommandCount specifies the exact

<a id="execution-algorithm"></a>

### Execution algorithm

The semantics of this API are defined with the following pseudo-code:

Non-NULL pCountBuffer:

```cpp
// Read draw count out of count buffer
UINT CommandCount = pCountBuffer->ReadUINT32(CountBufferOffset);
CommandCount = min(CommandCount, MaxCommandCount);

// Get pointer to first command argument
BYTE* Arguments = pArgumentBuffer->GetBase() + ArgumentBufferOffset;

for(UINT CommandIndex = 0; CommandIndex < CommandCount; CommandIndex++)
{
    // Interpret the data contained in *Arguments
    // according to the command signature
    pCommandSignature->Interpret(Arguments);
    Arguments += pCommandSignature ->GetByteStride();
}
```

NULL pCountBuffer:

```cpp

// Get pointer to first command argument
BYTE* Arguments = pArgumentBuffer->GetBase() + ArgumentBufferOffset;

for(UINT CommandIndex = 0; CommandIndex < MaxCommandCount;CommandIndex++)
{
  // Interpret the data contained in *Arguments
  // according to the command signature
  pCommandSignature->Interpret(Arguments);
  Arguments += pCommandSignature ->GetByteStride();
}
```

<!-- d3d12-review-alert:begin:indirect-execution:N-zero-state:0 -->

> [!WARNING]
> **Authored synthesis - human review pending.**
>
> A command count of zero executes no records. A record whose direct workload launches no primitives, groups or rays still occupies its place in the record sequence; later records and incrementing-constant indices do not collapse around it. No-work does not waive signature, resource, pipeline, alignment or recording context validity. After the call, affected state follows the canonical [indirect reset/leakage rules](command-list-state.md#indirect), including when no records execute or generated work is predicated off; unaffected state is not cleared.

<!-- d3d12-review-alert:end:indirect-execution:N-zero-state:0 -->

<a id="execute-validation"></a>

### Runtime validation and byte extents

<!-- d3d12-review-alert:begin:indirect-execution:N-execute-validation:0 -->

> [!WARNING]
> **Authored synthesis - human review pending.**
>
> The runtime validates four-byte alignment of both byte offsets, buffer resource dimensions, the argument buffer extent implied by the maximum command count and signature stride, count buffer extent when present, command list type and command signature node compatibility. A count buffer containing zero does not reduce the extent that must be valid for `MaxCommandCount`.

<!-- d3d12-review-alert:end:indirect-execution:N-execute-validation:0 -->

<!-- d3d12-review-alert:begin:indirect-execution:N-execute-validation:1 -->

> [!WARNING]
> **Authored synthesis - human review pending.**
>
> Let `S` be `ByteStride`, `P` the sum of the [payload byte sizes](#argument-records), `M` be `MaxCommandCount`, `A` be `ArgumentBufferOffset` and `W` the argument buffer's byte width. For nonzero `M`, the argument range must satisfy:

<!-- d3d12-review-alert:end:indirect-execution:N-execute-validation:1 -->

```text
A + (M - 1) * S + P <= W
```

<!-- d3d12-review-alert:begin:indirect-execution:N-execute-validation:3 -->

> [!WARNING]
> **Authored synthesis - human review pending.**
>
> The arithmetic must not overflow. The payload of the last record must fit; record-end padding after that final payload need not exist. For a present count buffer of width `C`, the selected four bytes require `CountBufferOffset + 4 <= C`, without overflow. These checks use the maximum API count, not `min(MaxCommandCount, GPUCount)`. When `MaxCommandCount` is zero, the runtime skips argument range size validation; alignment, buffer type and recording context requirements remain. A present count buffer still designates a valid four-byte count.

<!-- d3d12-review-alert:end:indirect-execution:N-execute-validation:3 -->

<!-- d3d12-review-alert:begin:indirect-execution:N-execute-validation:4 -->

> [!WARNING]
> **Authored synthesis - human review pending.**
>
> **History:** Earlier behavior required the final record's stride padding to fit as well. This was corrected. The final-payload extent above is the current contract.

<!-- d3d12-review-alert:end:indirect-execution:N-execute-validation:4 -->

<!-- d3d12-review-alert:begin:indirect-execution:N-execute-validation:5 -->

> [!WARNING]
> **Authored synthesis - human review pending.**
>
> Argument and count storage must support indirect argument reads under the [resource/heap contracts](resources.md#heap-types). In particular, a READBACK heap's fixed COPY_DEST usage does not satisfy indirect argument access. The public reference's phrase “any heap type” does not override this restriction. Protected argument/count buffers are prohibited.

<a id="argument-initialization"></a>

## Argument initialization and synchronization

<ins><!-- d3d12-review-inline:begin:indirect-execution:A-18.6.5.1:0 -->Parameters to indirect draws/dispatches can be initialized via standard ways of writing data into buffers, such as copy commands or rendering.<!-- d3d12-review-inline:end:indirect-execution:A-18.6.5.1:0 --></ins>

<ins><!-- d3d12-review-inline:begin:indirect-execution:A-18.6.5.1:1 -->Counter-based scenarios involve a variable amount of data that has been written to a buffer, via pixel shader/compute shader unordered access views with append or counter semantics. One might want to issue an indirect draw/dispatch in such a way that all of the entries in a variable length array of structures written to a buffer are fed back into the pipeline.<!-- d3d12-review-inline:end:indirect-execution:A-18.6.5.1:1 --></ins>

<ins><!-- d3d12-review-inline:begin:indirect-execution:A-18.6.5.1:2 -->In D3D12, the application allocates the [32-bit UAV counter storage](counters-queries-and-predication.md#application-counters) and supplies its [counter resource association](binding.md#buffer-uav). The application can copy the counter bytes with [CopyBufferRegion](resource-operations.md#copybufferregion), place them in a count buffer, or use shader work to produce workload arguments. The explicit counter byte operations and their [copy/clear interactions](resource-operations.md#counter-interactions) do not implicitly copy or clear a separately associated counter.<!-- d3d12-review-inline:end:indirect-execution:A-18.6.5.1:2 --></ins>

<ins><!-- d3d12-review-inline:begin:indirect-execution:A-18.6.5.1:3 -->When a copied UAV count is used as a way to recirculate variable length arrays of structures back into the pipeline, the application must be aware that there is no indication of whether the buffer holding the variable length data ran out of space. If the count is too high for the amount of space in the buffer, it means that during initialization when the buffer got full, subsequent writes were discarded, yet the counter continues going. The intent here is to efficiently enable scenarios where the application knows the worst case amount of data that could be written and allocates appropriately (or is otherwise somehow robust to having the last elements missing due to buffer full). Calling an indirect draw with a vertex count that is too high behaves predictably — attempts to read past the end of a vertex buffer have well defined [input fetch bounds semantics](vertex-processing.md#bounds).<!-- d3d12-review-inline:end:indirect-execution:A-18.6.5.1:3 --></ins>

<ins><!-- d3d12-review-inline:begin:indirect-execution:A-18.6.5.1:4 -->The [UAV counter/storage rules](binding.md#buffer-uav) define the actual storage and association. The indirect command count clamp limits the number of *records*, not a vertex/group/ray count in one record. Fetching an indirect argument record beyond its argument buffer is a different invalid range.<!-- d3d12-review-inline:end:indirect-execution:A-18.6.5.1:4 --></ins>

<ins><!-- d3d12-review-inline:begin:indirect-execution:A-18.6.5.1:5 -->[Stream output filled size storage](geometry-shaders-and-stream-output.md#filled-size) counts bytes, not command records. It is not interchangeable with a 32-bit command count merely because both occupy four bytes. The application must produce the correctly interpreted draw or dispatch field values.<!-- d3d12-review-inline:end:indirect-execution:A-18.6.5.1:5 --></ins>

No special indirect argument resource creation flag is required. The [buffer description](resources.md#buffer-description) and [resource flags](resources.md#resource-flags) still govern creation.

>
> The legacy alternative uses `D3D12_RESOURCE_STATE_INDIRECT_ARGUMENT` for argument and count reads, with applicable [transition/UAV barriers](synchronization.md#legacy-barriers) and [promotion/decay](synchronization.md#legacy-promotion-and-decay). [Cross-queue completion](execution.md#queue-waits) and object/resource lifetime remain separate requirements. The common synchronization rules, not a command count value or CPU recording order alone, govern when produced bytes are available to indirect execution.

<!-- d3d12-review-alert:end:indirect-execution:N-sync:3 -->

## Worked command signature layouts

<a id="example-indexed"></a>

### Indexed multidraw with record-end padding

In this example, the indirect argument buffer generated by the
application holds an array of 36-byte structures. Each structure only
contains the 5 parameters passed to DrawIndexedInstanced (plus padding).

The code to create the command signature description is:

```cpp
D3D12_INDIRECT_ARGUMENT_DESC Args[1] = {};
Args[0].Type = D3D12_INDIRECT_ARGUMENT_TYPE_DRAW_INDEXED;

D3D12_COMMAND_SIGNATURE_DESC ProgramDesc = {};
ProgramDesc.ByteStride = 36;
ProgramDesc.NumArgumentDescs = 1;
ProgramDesc.pArgumentDescs = Args;
```

The layout of a single structure within an indirect argument buffer is:

<!-- d3d12-review-alert:begin:indirect-execution:D-example-indexed:4 -->

> [!WARNING]
> **Mixed source and authored adaptation - human review pending.**
>
> | | |
> |---|---|
> Bytes 0:3|     `IndexCountPerInstance`
> Bytes 4:7|     `InstanceCount`
> Bytes 8:11|    `StartIndexLocation`
> Bytes 12:15|   `BaseVertexLocation`
> Bytes 16:19|   `StartInstanceLocation`
> Bytes 20:35|   `Padding`

<a id="example-root-vb"></a>

### Root constants and vertex buffer

In this example, each structure in an indirect argument buffer changes 2
root constants, changes 1 vertex buffer binding, and performs 1 drawing
non-indexed operation. There is no padding between structures.

The code to create the command signature description is:

```cpp
D3D12_INDIRECT_ARGUMENT_DESC Args[4] = {};
Args[0].Type = D3D12_INDIRECT_ARGUMENT_TYPE_CONSTANT;
Args[0].Constant.RootParameterIndex = 2;
Args[0].Constant.DestOffsetIn32BitValues = 0;
Args[0].Constant.Num32BitValuesToSet = 1;
Args[1].Type = D3D12_INDIRECT_ARGUMENT_TYPE_CONSTANT;
Args[1].Constant.RootParameterIndex = 6;
Args[1].Constant.DestOffsetIn32BitValues = 0;
Args[1].Constant.Num32BitValuesToSet = 1;
Args[2].Type = D3D12_INDIRECT_ARGUMENT_TYPE_VERTEX_BUFFER_VIEW;
Args[2].VertexBuffer.Slot = 3;
Args[3].Type = D3D12_INDIRECT_ARGUMENT_TYPE_DRAW;

D3D12_COMMAND_SIGNATURE_DESC ProgramDesc = {};
ProgramDesc.ByteStride = 40;
ProgramDesc.NumArgumentDescs = 4;
ProgramDesc.pArgumentDescs = Args;
```

The layout of a single structure within the indirect argument buffer is:

>
> | | |
> |---|---|
> Bytes 0:3|Data for root parameter index 2
> Bytes 4:7|Data for root parameter index 6
> Bytes 8:15|Virtual address of VB (64-bit)
> Bytes 16:19|VB size
> Bytes 20:23|VB stride
> Bytes 24:27|VertexCountPerInstance
> Bytes 28:31|InstanceCount
> Bytes 32:35|StartVertexLocation
> Bytes 36:39|StartInstanceLocation

<a id="driver-lifetime"></a>

### Driver object lifetime and execution inputs

<!-- d3d12-review-alert:begin:indirect-execution:WE-signature-lifetime:0 -->

> [!WARNING]
> **Authored synthesis - human review pending.**
>
> The runtime supplies the private storage reported by the sizing DDI through `D3D12DDI_HCOMMANDSIGNATURE`. The driver initializes that storage and must not free it.

<!-- d3d12-review-alert:end:indirect-execution:WE-signature-lifetime:0 -->

<!-- d3d12-review-alert:begin:indirect-execution:WE-signature-lifetime:1 -->

> [!WARNING]
> **Authored synthesis - human review pending.**
>
> On failed creation, the driver unwinds its partial state and additional allocations. DestroyCommandSignature is called only after successful creation and releases driver-owned allocations without freeing runtime-supplied private storage. The runtime keeps the associated root signature alive for the command signature's lifetime.

<!-- d3d12-review-alert:end:indirect-execution:WE-signature-lifetime:1 -->

<!-- d3d12-review-alert:begin:indirect-execution:WE-signature-inputs:0 -->

> [!WARNING]
> **Authored synthesis - human review pending.**
>
> The driver copies any command signature creation metadata needed after the call. It must not retain `pArgumentDescs`.

<!-- d3d12-review-alert:end:indirect-execution:WE-signature-inputs:0 -->

<!-- d3d12-review-alert:begin:indirect-execution:WE-indirect-roles:0 -->

> [!WARNING]
> **Authored synthesis - human review pending.**
>
> `PFND3D12DDI_EXECUTE_INDIRECT` receives argument/count buffer placements by value. `BaseAddress.UMD` contains a driver resource handle and resource-relative byte offset. The no-count-buffer form has a null resource handle and zero offset.

<!-- d3d12-review-alert:end:indirect-execution:WE-indirect-roles:0 -->

Both of the following implementations are acceptable:

- Make the GPU command processor interpret the indirect argument
    buffer contents in the application-defined format

- Allocate enough storage in the current command buffer to hold
    MaxCommandCount draws. Execute a compute shader to transform from
    the application-specified format to a hardware-specific format in
    the allocated command buffer space.
